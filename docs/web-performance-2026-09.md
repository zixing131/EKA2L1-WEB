# Web 主循环性能优化（2026-09）

基线提交：`21efc5f28`。优化仅涉及 Web 主循环与回归页，保留 CPU 时间预算、输入轮询、音频补充和图形队列处理。

## 空闲调度

`system::loop()` 返回 0 表示终止，而非空闲。旧 Web 循环将静止的计算器每帧执行到 64 次上限，性能日志也将这些空转误记为 CPU 预算耗尽。

每次执行后，在内核锁内检查调度器当前线程；没有可运行线程即退出该帧的 guest 执行。下一个浏览器帧仍会处理输入和重新调度，定时器线程照常运行。

浏览器中使用同一 Nokia 5320 ROM/RPKG 和计算器的静止画面验证：

- 每帧平均调度次数：64 → 1，减少 98.4% 的调度调用。
- 空闲 `budget_hit`：原来每帧触顶，优化后为 0。
- 优化后的 `avg_guest_cpu` 观测为 0.007–0.009 ms/帧；旧日志只有 0.1 ms 精度，不据此计算整机 CPU 降幅。

## 帧率限制

旧实现每次接受 RAF 后重新计时，导致上限取决于刷新率的整数分频。新实现保留目标帧的时间点，小幅抖动允许 0.5 ms 容差；长时间停顿直接跳过过期帧，避免恢复后补跑。

10 秒确定性时间戳测试，目标 60 次更新/秒：

| RAF 刷新率 | 优化前 | 优化后 |
| --- | --- | --- |
| 60 Hz | 60 | 60 |
| 90 Hz | 45 | 60 |
| 120 Hz | 60 | 60 |
| 144 Hz | 48 | 60 |
| 165 Hz | 55 | 60 |
| 240 Hz | 60 | 60 |

以上是主循环调度频率，不是所有游戏都能达到的渲染 FPS。CPU、GPU 和游戏内部定时仍会限制实际帧率。

## 验证

- Emscripten 5.0.7 Release 构建。
- 229 个测试、5911 条断言通过。新增测试覆盖不同刷新率、15/30/60/120 上限、RAF 抖动、长时间停顿与运行时切换。
- 浏览器计算器验证 `6 + 9 = 15`，解释器模式空闲调度同样降为每帧 1 次且数字输入正常；Jelly Chase 菜单持续动画正常。各取 15 个日志窗口，菜单实际渲染率前后均约 12 FPS，每帧调度次数从 64 降至约 3；本次未将其计为游戏 FPS 提升。
- `smoke.html` 保留独立 MEMFS，并增加可即时切换的 30/60/120 帧上限；浏览器实测切到 30 后约每秒 30 次主循环，再提高上限可正常恢复。
- 性能日志将 guest CPU 耗时显示到 0.001 ms，区分空闲让出与预算耗尽。
