# Super Miners Web 回归

样本：`Super Miners.sis`，应用 UID `0x2002517C`。SIS SHA-256：
`108f22cd11fbab6bc379e74128261098d7e7be259effa318b27783c8bb1a358f`。

## 崩溃原因与修复

游戏固定绘制 360×640。5320 的 240×320 屏幕不适合这个安装包，测试改用本机 Nokia 5800 的 ROM/RPKG。

但分辨率匹配仍不足以避免崩溃：构造函数根据 `HAL::Get(EManufacturer)` 的 Nokia 值 2，选择直接访问屏幕内存的路径，并硬编码 **2048 像素/行**。这与模拟器的屏幕布局不一致。5320 和 5800 分别在 `0xC926C000`、`0xC9306000` 写越界，游戏 PC 都是代码段偏移 `0x8C8C`，最终以 `KERN-EXEC 3` 退出；关闭 JIT 后也能复现原始问题。

加载器现在对已验证的这个版本选择游戏内置的 `CFbsBitmap` 绘制路径：

- 在 E32 解压后、代码段创建及首次执行前修改内存中的一条 ARM 比较指令。
- 检查 UID、代码长度 `0x764D0`、构造函数序言和渲染器选择指令签名，任何不匹配均不修改。
- 代码偏移 `0x86A0` 的 `CMP r0,#2` 改为 `CMP r6,#1`。序言将被调用者保存寄存器 r6 置零，因此 NE 分支选择位图路径及 360 像素行宽。
- 保留原有绘制逻辑、导入和重定位位置，SIS 与磁盘上的游戏程序保持原样。

## 加载缓慢的后续原因

原 Web 空闲检查仅检查 `current_thread == nullptr`。非阻塞调度器在唯一线程用完时间片时，会将线程重新放回就绪队列，并暂时返回空的当前线程。主循环把这个切换间隙当成真正空闲，过早结束浏览器帧中的 CPU 执行，使游戏的资源解压看起来停在空白画面。

现在在内核锁内同时检查当前线程与两个优先级就绪位图；只有两者均为空才让出。仍保留帧时间预算和切片上限，不改动调度器的选线程规则。实测解压时每帧不再只运行约 2 个切片，能继续使用当前帧预算，随后进入语言菜单和游戏关卡。

## 验证与复现

- Emscripten 5.0.7 Release 完整构建通过。
- 231 个测试、5930 条断言通过；新增 19 条断言覆盖补丁匹配、重复调用、其他 UID、修改过的指令、不同代码长度、截断及空指针。
- Nokia 5800 + 默认 JIT：厂商画面、语言菜单、人物选择、第一关和人物移动均正常；页面重启后仍能进入菜单，270° 横屏显示正常。
- 默认 5320 计算器仍可输入；静止画面每帧仅 1 个切片、`budget_hit=0`，空闲优化仍有效。
- 回归页增加可选 SIS/SISX 安装、同源测试链接指定固件与程序包、画面旋转和诊断日志。安装与运行仍只使用 MEMFS；刷新重新安装，不读取或覆盖正式页面存档。

启动 `python3 buildscript/serve_regression.py`，打开 `smoke.html`，选择匹配的 5800 ROM/RPKG 及该 SIS，再点击「运行回归」。游戏会自动启动。可将「画面方向」设为 270°，横向查看游戏。
