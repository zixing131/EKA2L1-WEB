# iOS Port — Investigation Log Index

Each entry below is a deep-dive into a non-trivial bug or design question hit during
the iOS port: symptom, how it was narrowed down, and the conclusion/fix. See
`AGENTS.md` for when and how to add a new one — no fixed template, write whatever
fits the problem. Newest first.

| Date | Doc | Summary |
|---|---|---|
| 2026-07-16 | [`User::After` completion null-deref on teardown](./ios-notify-sleep-teardown-null-deref.md) | TestFlight crash in the timing thread: `thread::notify_sleep` (the `User::After` completion path) dereferenced the guest `TRequestStatus*` without checking that the host translation succeeded. `ntimer::advance()` runs event callbacks outside the timing lock, so a thread can be torn down (its stack/data page unmapped) between the wakeup event being popped and the callback running, making the translation return null. Fixed by null-guarding the host pointer, matching the existing `notify_info::complete()` guard. |
| 2026-07-16 | [System-language switch app-list reload](./ios-language-switch-applist-reload.md) | Changing the guest system language didn't relabel the home app list until relaunch. `applist_server` caches each caption in its first-loaded language and `rescan_registries()` skips reloading a registry whose `.rsc` mtime is unchanged, so a language switch alone leaves the old names. Fixed by clearing the cached registrations in `setSystemLanguageCode:` (forcing a full reload under the new language) and posting an invalidation so `ContentView` re-scans the list live. |
| 2026-07-16 | [6680 application launch exit](./ios-6680-avkon-app-launch-exit.md) | `sdancer` left with `KErrNotFound` before its active scheduler started because the epoc80 Messaging client registry could not find the SMS MTM. EKA2L1 emitted 136-byte EKA1 MTM records, omitting capability fields until epoc81a, while the 6680 fixed-layout reader expected the 148-byte format already used by epoc80. Writing those fields from epoc80 restores the registry and application launch while preserving epoc6/7. Calculator was a misleading control with incompatible cross-firmware state, not the same Avkon bug. |
| 2026-07-15 | [Legacy AIF icon mask polarity](./ios-legacy-aif-icon-mask-polarity.md) | Asphalt 2 on the 6680 installed successfully but showed a blank app-list icon. Its legacy AIF pairs an 8bpp colour icon with a 1bpp gray2 binary mask whose white backdrop must be inverted; the recent `<=8bpp` soft-mask rule instead cut out the foreground. Mask handling now distinguishes 1bpp binary masks, 2-8bpp soft opacity, and 12bpp+ colour-key masks, preserving 6680 ROM and newer 5320 icons. |
| 2026-07-14 | [Asphalt 6 menu car material](./asphalt6-menu-car-material-investigation.md) | RESOLVED. iOS bitmap FBOs (backing EGL window surfaces too) had no depth attachment, so opaque car-body draws were later painted over by translucent floor/glow passes in painter's order. Fixed by giving iOS bitmap FBOs a packed depth-stencil renderbuffer instead of the disabled depth-texture path. Documents the elimination method (per-draw GL state dumps, sequential framebuffer captures) and a table of disproven hypotheses. |
| 2026-07-13 | [X7 Asphalt 6 launch & race path](./ios-asphalt6-x7.md) | Getting Asphalt 6 to boot and race on X7/Belle required ~10 general Symbian^3/Belle emulation fixes (SCDV depth-stencil surface, Belle executive table, ROM DLL loading, MMF Stop, ALF transition policy, Window Server screen-mode query, Accessory Server, Loader PDD, versioned patch DLL bundling). Also covers a real-device audio-teardown/kernel-lock watchdog deadlock and the SCDV binary-patch build tooling. |
| 2026-07-13 | [iOS CoreMotion async IPC crash](./ios-sensor-async-ipc-crash.md) | TestFlight crash: a CoreMotion callback read/removed a pending IPC context before taking the kernel lock, so a racing guest StopListening/CloseChannel freed its descriptors first, and the host then wrote through a null pointer. Fixed by serializing sensor completions inside the kernel lock with lifetime-safe callback state and validating requester/descriptor liveness before writing. General Sensor Framework/IPC fix. |
| 2026-07-11 | [5320 Camera panic 49](./ios-5320-camera-panic49.md) | Device-only Camera panic: three combined bugs — the SVC ROM-patch trampoline read/wrote a stale thread context instead of the live CPU state, ECam dispatcher was missing `ECamDuplicate`, and the iOS camera backend declared capabilities (zoom/contrast/etc.) it didn't implement, causing a guest Leave/access violation. All three are general kernel/service fixes, verified on-device. |
| 2026-07-11 | [Camera menu over viewfinder](./ios-camera-menu-over-viewfinder.md) | Device-only: the Camera Options menu flashed once then got covered by the viewfinder. The viewfinder redraws via the incremental client-redraw path, which doesn't respect multi-rect clipping reliably and is never recomposited by a full server redraw, so it bleeds over the menu above it. Fixed by forcing a full server redraw whenever a partially-occluded window does a client redraw. |
| 2026-07-11 | [ipc_msg refcount UAF](./ios-ipc-msg-refcount-uaf.md) | TestFlight users saw random crashes when repeatedly opening different apps. `free_msg` force-released an `ipc_msg` still referenced by a server, letting the slot recycle to a new thread while the stale completion still fired against it — corrupting the refcount and eventually freeing a still-referenced kernel thread, hit later via a dangling vtable call during teardown. Fixed with reference-respecting free, an underflow guard, and related cleanup-ordering fixes. |
| 2026-07-10 | [TestFlight crash triage, round 2](./ios-testflight-crash-triage-r2.md) | Second-pass triage of 5 new crash clusters (24 logs), resolved into 6 independent root causes, all fixed: a timer thread still firing during system teardown, wipeout destroying chunks before processes (UAF), a codedump collector holding a freed pointer, never-unlinked parent/child process pointers, a guest-controlled bitmap-hash out-of-bounds read, an iOS applist-rescan-vs-reboot lock race, an audio-stream teardown-order UAF, and an EGL surface with a dangling window-observer pointer. |
| 2026-07-08 | [N-Gage installer popup & game launch](./ios-ngage-installer-popup-and-game-launch.md) | Two N-Gage bugs. Fixed: the installer's "Installation complete" popup never appeared because redraw-window completions only triggered incremental client compositing; fixed by forcing a full recomposite on changed redraw completion. Root-caused but unfixed: starting the DRM-cracked game "ONE" black-screens because the launcher UI thread is suspended mid-handoff and never resumed — specific to that title's activation-server handshake. |
| 2026-07-08 | [N-Gage ONE launch deadlock — handoff](./ios-ngage-one-launch-deadlock-handoff.md) | Handoff doc for the unresolved N-Gage "ONE" launch deadlock: repro steps, confirmed facts (backend-independent, not render/input, launcher thread stuck suspended with unconsumed completions), reusable diagnostic probes (scheduler idle dump, host sampling, DSA frame probe), and suggested next steps tracing who suspends/resumes the launcher thread via PlayServer's handshake. |
| 2026-07-08 | [TestFlight crash triage, round 1](./ios-testflight-crash-triage.md) | First-pass triage of 25 crash clusters (72 logs). Main cause (fixed): applist's background thread pool called `fbs_server::create_bitmap` concurrently without a lock, corrupting the shared chunk allocator's free list; fixed with a recursive allocator lock. Also fixed: an audio DSP completion UAF on a destroyed guest thread, a property-cancel completion UAF, and a wipeout-teardown ordering crash. Remaining graphics/freetype crashes deferred pending re-triage. |
| 2026-07-07 | [Stray-signal accounting — follow-up](./stray-signal-accounting-followup.md) | Not root-caused yet; a roadmap for whoever picks it up next. `E32USER-CBase 46` stray signals come from HLE services over-signaling the guest request semaphore; current code relies on an absorption mechanism in `wait_for_any_request` as a stopgap (works, but is a compensating layer). Lays out the accounting model, prior fixes, quantified evidence, and a path to a real per-request accounting rework. |
| 2026-07-05 | [iOS productization checklist](./ios-productization-checklist.md) | Not an investigation — an App Store readiness checklist. Core pipeline (install → SIS → play → input/audio/haptics) works; this pass added icon/launch-screen/version/privacy-manifest, onboarding, English string catalog, and instant-apply settings. Tracks remaining P0–P3 gaps (store screenshots, compliance review, MIDI banks, iPad layout, crash reporting, CI archive pipeline). |
| 2026-06-15 | [Metal via ANGLE plan](./ios_metal_angle_plan.md) | Plan to run the existing GLES renderer through ANGLE's Metal backend (EGL) instead of a native Metal/Vulkan rewrite. Hardware-accelerates the iOS Simulator (software GLES today); device stays GPU-accelerated either way. Phase 0 proved GLES3-over-Metal works in the simulator; later phases reached render parity, but simulator FPS A/B came back neutral — the present is already double-buffered, so the interpreter, not the renderer, was the real ceiling. |
| 2026-06-14 | [dyncom optimization plan](./dyncom_optimization_plan.md) | Interpreter optimization plan and landing log. Landed: ReadCode-via-TLB, inlined `AddWithCarry`, block-linking L1, inline memory fast path, VFP MAC fast path, LDM/STM block-cursor, all backed by a new differential test harness. Shifter specialization and lazy NZCV flags were tried, profiled, and rejected as neutral/regressive. Conclusion: general dispatch/ALU wins are exhausted; only JIT (off-limits on iOS) would help further, and the simulator is GPU-render-bound anyway. |
| 2026-06-14 | [Snakes / dyncom performance](./ios_snakes_perf.md) | Two fixes landed: ASID-tag the dyncom instruction cache so it survives thread/process context switches (removed ~17% re-decode thrash), and cap the simulator's software-GLES present scale (~4x less fill). Follow-up: after re-adding a double-buffered present, the sim became co-limited by the interpreter and Apple's software GLES rasterizer; a CMP+B fusion experiment was neutral and reverted, an LDM/STM block-cursor optimization was kept. |
| 2026-06-14 | [Final Battle timer stray signal](./ios-final-battle-timer-stray.md) | Final Battle panicked ~1 minute into gameplay (`E32USER-CBase 46`). A periodic timer completed a request in the narrow window after the guest issued it but before calling `SetActive()`, so the active-scheduler couldn't find a ready object for the resulting signal. Fixed by deferring such completions briefly (bounded retries) until `SetActive()` lands — the earlier "absorb stray signals" approach deadlocked menu input instead. |
| 2026-06-13 | [Calculator Options menu hang](./ios-calculator-options-menu-hang.md) | Two-layer bug. Layer 1 (fixed): an unimplemented synchronous window-server opcode never called `ctx.complete()`, permanently blocking the guest. Layer 2 (root-caused, not fixed): once unblocked, the menu still doesn't render because AknIconServer's icon rendering leaves `KErrNotSupported` — a ROM draw-device factory only accepts 32bpp display modes but receives the standard 16-bit icon format. Needs a bespoke icon-HLE feature, deferred. |
| 2026-06-05 | [Optimized-build Snakes stray signal](./ios-optimized-build-snakes-stray-signal.md) | Optimized/Release device builds panicked Snakes (`E32USER-CBase 46`). The synchronous HLE sleep path deque'd the thread without requesting a reschedule, so the guest CPU kept executing an already-waiting thread; a later wake-up transition raced `WaitForAnyRequest` into a stray-signal panic. Fixed by requesting a reschedule immediately after a synchronous sleep deques the current thread. Verified on-device across Release and RelWithDebInfo. |
| 2026-06-03 | [Device missing patch DLLs](./ios-device-missing-patch-dlls.md) | Real-device Snakes was black-screen/silent while the simulator worked fine, despite byte-identical ROM/app/data. The device build's HLE patch-DLL staging used a `__FILE__`-relative dev-machine path that only exists on the simulator's build host — the device build never had a patch directory at all. Fixed by bundling patch DLLs into the app and staging from the bundle first. General lesson about `__FILE__`-relative resource staging on iOS. |
| 2026-06-02 | [App-list icons (SVG/MIF decode)](./ios-applist-icons.md) | Implemented app-list icon decoding (mif/lunasvg → mbm → fbs `get_icon` fallback) rasterized to PNG for SwiftUI. Follow-up fix: empty-caption app entries produced an empty sanitized cache filename, crashing `pystr`'s strip on an empty string during scroll-triggered lazy icon loading; fixed with empty-string guards, a uid-based filename fallback, and icon-decode mutex serialization. |
| 2026-06-02 | [Native AudioUnit backend](./ios-audiounit-backend.md) | Replaced the cubeb audio shim with a native AURemoteIO + AVAudioSession backend (`audiounit_ios`), dropping cubeb from the iOS build entirely. Services get a real `audio_driver` and load the audio patch DLLs. Follow-ups (audible-sound confirmation, MIDI bank staging, mic input) remain untested. |
| 2026-06-02 | [Calculator EAGL magenta screen](./ios-calculator-eagl-magenta.md) | Calculator rendered as a magenta blank screen. The OGL backend's "framebuffer 0" bind was hardcoded to the GL default framebuffer, which doesn't exist on iOS GLES — draws were silently dropped onto Apple's uninitialized-magenta EAGL drawable. Fixed with a virtual `swapchain_framebuffer()` so `gl_context_eagl` can return its real FBO. Also fixed several default-driver null-pointer crashes and present-timing ordering along the way. |
| 2026-06-02 | [Document picker import](./ios-document-picker-import.md) | Implemented a device-centric home screen and file-import flow: `ImportDeviceView` installs ROM/RPKG via the real installer, "+" imports SIS through `UIDocumentPicker` with security-scoped URLs staged to a temp folder first. Also fixed a SwiftUI bug where two overlapping `.fileImporter` modifiers silently dropped one of them. |
| 2026-06-02 | [DSP / FFmpeg reconnection](./ios-dsp-ffmpeg.md) | Wired real FFmpeg codecs back into the iOS simulator build via an out-of-tree cross-build script, replacing the PCM-only fallback. Device build and real compressed-audio decoding verification are still pending. |
| 2026-06-02 | [Guest PC=0 deadloop](./ios-guest-pc0-deadloop.md) | Newly launched guest apps immediately faulted with a wall of access violations from PC=0. Found via cross-platform repro on macOS arm64 Qt: Apple Silicon uses 16KB host pages, but EKA2L1's memory model called `mprotect` with 4KB-granularity ranges, silently rejected by the kernel (EINVAL), leaving pages `PROT_NONE`; a later push/pop through such a page corrupted the stack frame. Fixed by aligning commit/protect ranges to the host page size. |
| 2026-06-02 | [Log flood pins CPU](./ios-log-flood-cpu.md) | N97/S60v5 Calculator showed black screen + 100% CPU. The iOS frontend never applied the configured log filter and defaulted to full trace-level logging with synchronous flush-on-debug, so every context switch and dyncom VFP op was flushed to disk. Fixed by mirroring the desktop's log-level downgrade in the iOS frontend. Note: this only fixed the CPU flood — N97 Calculator's underlying black screen is a separate, still-open issue. |
| 2026-06-02 | [Mount chunk SIGBUS](./ios-mount-chunk-sigbus.md) | Mounting a ROM SIGBUS'd during kernel chunk zero-fill. Same root cause as the PC=0 deadloop: Apple Silicon's 16KB host pages vs EKA2L1's 4KB-granularity `mprotect` calls being silently rejected. Fixed by the shared host-page-size alignment fix. |
| 2026-06-02 | [mprotect silently strips W^X](./ios-mprotect-wx-strip.md) | Creating the dispatcher trampoline chunk (RWX) crashed on first write. iOS's sandboxed arm64 W^X enforcement silently strips `PROT_WRITE` from an RWX `mprotect` request. Since the dyncom interpreter never executes guest pages as host code, `PROT_EXEC` is redundant there; fixed by stripping it from iOS protection translation (temporary until stage-4 JIT/MAP_JIT support). |
| 2026-06-02 | [Real ROM install pipeline](./ios-rom-install-pipeline.md) | Replaced the early hardlink-graft + hand-written `devices.yml` workaround with the real Android/desktop install pipeline (`install_device`/`install_rom`/`install_rpkg`), persisting the selected device across relaunches, plus a session mutex protecting concurrent install/boot/rescan operations. |
| 2026-06-02 | [SIS install silent write failure](./ios-sis-install-write-fail.md) | SIS installs reported success but left drive E empty. The SIS interpreter lower-cased the already-resolved host absolute path (not just the Symbian virtual path); on iOS's case-sensitive sandbox with a mixed-case container path, the lowercased path didn't exist so payload writes silently failed while the registry write succeeded. Fixed by only lower-casing the Symbian virtual path and propagating path-resolution failures instead of swallowing them. |
| 2026-06-02 | [Snakes stray-signal freeze](./ios-snakes-stray-signal.md) | Snakes froze at its splash screen (`E32USER-CBase 46`). HLE frame-pacing sleep leaked extra request-semaphore signals, and semaphore count could desync from active-scheduler ready state. Fixed by making frame-pacing sleep pure scheduler sleep, teaching `WaitForAnyRequest` to prefer a ready active object over blind absorption, and moving vsync notify completion under the kernel lock. An earlier theory blaming the same race for a device black screen was later disproven — see the missing-patch-DLLs doc. |
| 2026-06-02 | [VFS case-sensitive path resolution](./ios-vfs-case-sensitive-path.md) | ROM files with mixed-case names (e.g. `Wsini.ini`) failed to load on iOS. The case-insensitive path-resolution codepath force-lowercased the whole path, but the iOS sandbox's host filesystem is case-sensitive. Fixed by walking the path directory-by-directory on iOS, resolving each segment's real case via case-insensitive comparison. |
| 2026-06-02 | [S60v5 AVKON FEP / PtiEngine stall](./s60v5-avkon-fep-pti.md) | N97/S60v5 Calculator hangs black-screen at 100% CPU. Confirmed backend- and platform-independent (reproduces on desktop Qt): a general EKA2L1 gap in S60v5's AVKON FEP/PtiEngine and OpenVG startup handshake. Several fix attempts (ROM DLL patch by name, feeding a fake Zi kernel object) failed or were misdirected; deep investigation found the failure is actually non-deterministic and mostly precedes FEP entirely. Unresolved — use lightweight apps (Zip Manager) instead of Calculator on N97 for now. |
