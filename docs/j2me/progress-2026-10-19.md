## 10-17 之后的改动（未提交，效果待回归）

以下内容根据工作区 diff 和代码注释整理，**还没有跑过完整回归**，是否已让安装提交需要重新确认。

### 修复方向

1. **sisregistry `PropertyL`（opcode `0xC`）**
   `src/emu/services/src/sisregistry/sisregistry.cpp` 新增 `request_property`：按 key 返回包在 PKG 里
   用 `+(key=value)` 声明的整数属性，找不到返回 `KErrNotFound`。
   MIDP 安装插件在安装套件前会读 MIDP 运行时桩包（`MIDP.SIS`，`0x1000A46D`）的 key 1–4，
   以前这个 opcode 未实现、直接 `Complete(0)` 且不写值。
   子会话里未实现 opcode 的日志也加上了 pkg / arg0 / flags / 进程名。
2. **`ifeui.dll` 补丁在原始模式下关闭**
   旧补丁会跳过 `Run` 里 `this+0x418` 处的 `iFs.Connect()`，之后 MIDP 识别器
   （`midp2iferecognizer.dll`）和 JAD/JAR 匹配器用的就是 handle 为 0 的 `RFs`，
   这很可能就是 10-17 记录的 **Leave -8（KErrBadHandle）** 的来源。
   `midp2installerplugin.dll` 的补丁也在原始模式下关闭；`midp2silentmidletinstall` 的未签名策略补丁保留
   （相当于真机上用户点了确认）。
3. **原始模式下不再预建空的 `C:\private\101F875A\journal.db`**
   0 字节文件不是合法的 DBMS 数据库，交给 SWInst 自己创建。
   这和 10-17 记录的 SWInst **DBMS panic 2** 有关，是否就是根因待确认。
4. **applist**：非原生应用（MIDlet）排队注册时打一行 info 日志，用来确认安装最后一步有没有走到。

### 临时探针（只在 `leaveprobe=1` 时生效，提交前要清理）

- `svc.cpp`
  - `[inst-complete]` / `[ams-ipc]`：Installer / MIDP2SilentMIDletInstall 与 SystemAMS、AMSDb、javaregistry 之间的 IPC 发送和完成值。
  - `[handle-probe]`：session send 遇到坏 handle 时打线程、进程；handle 为 0 的前两次再 dump 上下文和栈上 48 个字。
- `fs.cpp` `[fs-probe]`：Java 相关进程或路径（`102033e6`、`101f875a`、`10203636`、含 `midlet`）的
  mkdir / delete / rename / replace / create / temp。
- `libmanager.cpp`
  - `[rec-probe]`：在 `midp2iferecognizer.dll+0xE0` 种 BKPT，打印传进来的 `RFs` 及其 handle，然后模拟原指令 `movs r4, r1` 继续执行。
  - `[watch-rfs]`：SWInst `Installer[101f875a]` 进程里监视地址 `0x70E3D8`（`jcfjadjarmatcher` 用的 `RFs`）的变化，
    每次 SVC 前比较。**地址是写死的**，只对当前 ROM / 当前加载布局有效。
