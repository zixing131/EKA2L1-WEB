# J2ME：guest J9 去 hook 化（2026-10-17）

接 [progress-2026-10-15.md](progress-2026-10-15.md)。方向：只走 guest IBM J9，不依赖 host MIDP 解释器。

## 现状判断

默认模式下“J9 在跑、画面黑”其实是：

- **guest J9 并没有执行游戏**。`libmanager.cpp` 里的 J9 hook 链（约 1.8 万行）一步步代跑 JCL 初始化
  （`com/symbian/j2me/midp/runtimeV2/Main`），卡住后把 Main 线程停到 `walk+0x3820` 的 `b .` 死循环
  （`g_j9_park_pc`），CPU 一直满载。
- 游戏字节码由 **host MIDP 解释器**（`j9_host_midp.cpp`，`host-attach`）执行。黑屏是因为它没实现
  `GameCanvas.getGraphics/flushGraphics/getWidth/getHeight`，`GameCanvas.paint` 也被跳过。
- AMS → J9 这一段也是旁路：`apply_ams_find_compat_patch` 把 AMS opcode 1 改成直接 `Complete(0)`、
  stub 掉 Launch、Find 未命中时伪造套件，然后由 host 自己 `spawn_j9_with_ams` 拉 J9，参数是 host 编的。

继续堆 hook 不会收敛，所以改为：**关掉所有 workaround，让真实组件跑，逐个修模拟器根因**。

## 新增：`?j9raw=1` 原始模式

`boot.js` 读 URL 参数后调用 `wasm_set_j9_raw(1)`（index / run 页都生效）。开启后：

- `apply_j2me_compat_patches` 对名字含 `j9` / `jcl` 的模块不打任何补丁、不种 BKPT；
- 不打 `midp2systemams` 的 AMS Find/Launch 补丁，也不打 `integrityserver` 的 `Complete(0)` 补丁；
- 主循环不做 host MIDP `j9_host_try_attach`；
- `interface.cpp` 不在 StubMIDP2 handoff 后自己 spawn J9（由真 AMS 去拉）；
- `process_command_line` 对 J9 也按真实语义返回完整命令行；
- `files.cpp` 不再为 integrity store（`\private\1028247a\*.drv/.log`）和 `java_*.properties` 造空文件。

仍保留：安装器同意框相关补丁（`midp2silentmidletinstall` 未签名策略、`midp2installerplugin`、`ifeui`）、
SWInst opcode 516 `-30472→0` 改写、fs/vfs/loader 的路径与别名兼容。

测试：`J9RAW=1 BASE=… node /tmp/pt/real4.js BounceTales.jar 30 --fresh`（index 与 run 都带 `j9raw=1`，并开 leaveprobe）。

## 已确认的事实

1. **命令行语义**：本 ROM 的 `User::CommandLine`（`euser.dll+0xB8A6`）是 SVC 0x17 的唯一调用者，
   构造 `TPtr8(ptr, MaxLength<<1)`，返回后 `SetLength(len>>1)`。所以内核必须按**字节**回长度，HEAD 正确；
   旧文档“ESTLIB 需要按字符数”的说法不对。默认模式下对 `j9midps60` 的特判等于故意只给 J9 前一半参数，
   这正是旧 hook 链调参时的环境。
2. **J9 原始首崩**（host 直接拉 J9 时）：`j9_23_midp2ams.dll` `.data+0x28`（RAM `0x3FFF0028`）的 `TDesC*`
   为空，`TDesC::Compare` 在 `euser.dll+0x5170` 读 0。反汇编：该槽只在启动 VM 的函数 `+0x5712` →
   选项构造 `+0x51B8` 里、命令行带 `-jar` / `-classpath`（`r6`）时由 `+0x5438` 写入；
   同一循环还认 `-path`、`-ide_port`、`-ide_server_mode`、`-ide_io_port`、`-Xbootclasspath/p:`。
   说明 host 编的参数和真 AMS 传给 VM 的不一样，所以改成让真 AMS 拉 J9。
3. **真 AMS 路径**：StubMIDP2 → `!MIDP.SystemAMS.MIDP2` opcode 1（suite `0x20000001`）返回 **-1**：
   AMS 不认识这个套件，因为安装没有提交。
4. **安装链（原始模式）**：`MIDP2SilentMIDletInstall` → SWInst（`swinstsvrui.exe` / `Installer[101f875a]`，
   插件 `midp2installerplugin.dll`、`midp2downloader.dll`、识别器 `midp2iferecognizer.dll`）。观察到：
   - 跨进程传 `RFile`（Duplicate opcode 96 / Adopt 97）全部成功，不是 KErrBadHandle 的来源；
   - integrity server 打开不存在的 `C:\Private\1028247A\E33BB68AF3FF60.drv/.log` → Leave -1；
   - `Installer` 去开 ROM 预装游戏 `C:\Private\101F875A\GuitarRockTour_Nokia5320_…jar`（不存在），
     随后 **panic DBMS 2**，SWInst 返回 -30471（`KSWInstErrUserCancel`）或进程直接死掉；
   - `midp2downloader` / `midp2iferecognizer` 里有 Leave -8（KErrBadHandle），来源未定位。
